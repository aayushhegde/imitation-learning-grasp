## Executive Summary

The original `0/12` strict result was not caused by a broken `evaluate_strict` harness. It had two
separate causes:

1. The submitted expert contained several deviations from the reference state machine. They made
   the teacher less robust and reduced demonstration quality.
2. More importantly, the original learner was a stateless one-frame MLP, while the expert was a
   stateful 13-phase controller. Some nearly identical observations require different actions after
   different phase dwell times. A deterministic mapping `action = f(current_observation)` therefore
   cannot reproduce the expert reliably.

The repaired pipeline first aligns and benchmarks the expert, then trains a GRU policy over complete
episode sequences using relative geometry and an auxiliary phase-prediction objective. On the same
fresh seeds `20000–20023`, the legacy stateless policy obtains `2/24` strict successes, while the
fixed recurrent policy obtains `11/24`. The corrected expert obtains `24/24` through the same flat
policy evaluator.

## Original Problems and Corrections

### 1. Incorrect object-velocity slices in E01

The submitted student decoder used:

```python
obj_velocity = main[10:13]
obj_angular_velocity = main[13:16]
```

In the Panda observation contract, indices `10:13` are object Euler angles. The correct slices are:

```python
obj_velocity = main[13:16].copy()
obj_angular_velocity = main[16:19].copy()
```

This error did not directly create the original `0/12`, because the old expert did not use the two
velocity fields. It was nevertheless a real interface error that would invalidate any future
velocity-aware feature or guard.

### 2. The actual grasp pose was not frozen at `DESCEND → CLOSE`

The corrected transition records the measured hand/object relationship when descent finishes:

```python
memory.grasp_offset = state.ee - state.obj
memory.grasp_target = state.ee.copy()
```

The submitted implementation instead constructed a nominal target later from the moving object and
the default offset. That allowed the hand to chase or push the object while closing.

### 3. `TEST_GRASP` could advance without proving that the cube had lifted

The submitted guard used finger width and a vertical hand/cube gap. It could advance on geometry that
looked like a grasp before the test-lift action had demonstrated that the cube moved with the hand.

The reference transition requires observed cube elevation:

```python
if state.obj[2] > 0.05:
    switch(ExpertPhase.LIFT_CLEAR)
```

If that evidence never appears before the timeout, the expert returns to `APPROACH` and retries.

### 4. The release transition checked the hand instead of the cube

The submitted `LOWER → OPEN` guard checked whether the end effector had reached its nominal target.
The corrected guard checks the task-relevant state:

```python
if np.linalg.norm(state.obj - state.goal) < cfg.place_tolerance:
    memory.release_target = state.goal + memory.grasp_offset
    switch(ExpertPhase.OPEN)
```

The hand can be at the nominal pose while the cube is still outside the placement tolerance. Opening
in that state creates avoidable release and stability failures.

### 5. The submitted notebook omitted the multi-seed expert benchmark

The completed student copy deleted the canonical `expert-benchmark` cell. It therefore proceeded to
data collection after only a single integration rollout. The fixed student edition restores the
benchmark immediately after E08.

This matters because the submitted expert produced 23 strict demonstrations from 24 attempts. Its
failed seed remained in `RETREAT_HOME` until timeout, a failure that the removed benchmark would have
made visible.

### 6. `TARGET_DEMOS` counted attempts rather than successful demonstrations

The old collection loop was:

```python
for seed in range(TARGET_DEMOS):
    trace = collect_trace(...)
    store.save(trace)
```

If the expert failed, the final dataset silently contained fewer than `TARGET_DEMOS` usable episodes.
The fixed loop keeps every attempt for diagnosis but continues until it has collected exactly the
requested number of strict, collision-free demonstrations. Quick mode now collects 40 successful
episodes; full mode requests 200.

### 7. E13 duplicated an environment constant

The submitted classifier hard-coded:

```python
STABLE_STEPS_REQUIRED = 12
```

The fixed classifier reads:

```python
info["required_stable_steps"]
```

This was not responsible for the old result because the current environment also requires 12 steps.
The change prevents silent configuration drift.

### 8. The instructor evaluator did not reset stateful policies

The original instructor evaluator was safe for the stateless MLP but did not call `policy.reset()`.
That would leak a recurrent hidden state from one evaluation episode into the next.

Both fixed notebooks now execute:

```python
if hasattr(policy, "reset"):
    policy.reset()
```

before every episode.

### 9. The original feed-forward BC target was structurally ambiguous

The expert uses hidden state that was absent from the learner input:

- one of 13 phases;
- `phase_steps`;
- frozen grasp and release targets;
- retry state.

At `CLOSE → TEST_GRASP`, the physical state can remain nearly unchanged while the correct vertical
action changes from holding position to lifting. At `OPEN → RETREAT_UP`, the same issue appears when
the correct action changes from holding the release pose to retreating upward.

The saved phase label was never provided to the original `HybridPolicy`, and the original DataLoader
shuffled individual timesteps. More demonstrations cannot remove this same-input/different-output
contradiction.

### 10. Success-only demonstrations did not cover the learner's failure states

The submitted diagnostics showed that every training row with an almost-zero gripper width was an
initial `APPROACH` state far from the cube. When the learner closed early near the cube and missed the
grasp, it entered an empty-closed-gripper state absent from the dataset.

The failed rollout then converged to:

```text
mean motion norm ≈ 0.000796
mean gripper logit ≈ -7.20
```

That is a confident `closed gripper + zero motion` attractor, not a simulator or action-sign error.

## The Repaired Learning Formulation

### Relative geometry

The fixed policy appends 11 task-relevant features to the original 22 values:

```text
object − end_effector        (3)
goal − end_effector          (3)
goal − object                (3)
||object − end_effector||    (1)
||goal − object||            (1)
```

The resulting model input has 33 dimensions. This exposes the translation-friendly geometry that the
controller otherwise has to rediscover from a small dataset of absolute coordinates.

### Episode-level recurrent training

The fixed policy uses:

```text
33D feature → Linear(128) + ReLU → GRU(128)
                                      ├─ 3D tanh motion head
                                      ├─ binary gripper head
                                      └─ 13-way auxiliary phase head
```

Episodes are split into disjoint training and validation sets before normalization. Timesteps remain
in episode order; padded positions are excluded with a mask. The loss is:

```text
SmoothL1(xyz)
+ 0.35 × BCE(gripper)
+ 0.15 × CrossEntropy(phase)
```

Inverse phase-frequency weights are clipped to `[0.25, 4.0]` for the action term so that long hold
phases do not completely dominate transition phases.

The phase is used only as a training target. The deployed policy does not receive a privileged phase
input; it carries only the GRU hidden state inferred from observation history.

## Which Changes Actually Caused the Improvement?

The expert corrections are necessary for a reliable teacher, but they are not sufficient to repair
the learner: the canonical instructor notebook already had the correct expert and its original saved
stateless BC result was still `0/12` strict.

The nonzero closed-loop result comes from the combined learning repair:

1. relative geometric features reduce sample complexity and grasp-alignment error;
2. recurrent state makes phase duration and action order representable;
3. auxiliary phase supervision makes that recurrent state easier to learn;
4. ordered episode training prevents sequence information from being destroyed;
5. per-episode reset prevents hidden-state leakage;
6. collecting exactly 40 successful episodes removes accidental demonstration-count variation.

Phase balancing or more stateless demonstrations alone should not be interpreted as the solution.
Separate diagnostic runs found that 200 successful demonstrations with the original stateless model
still produced only `1/100` strict success.

## Implications for the Augmentation Study

All three arms—real-only, real+CVAE, and real+noise—should use the same recurrent base policy and the
same real episode IDs. Only the additional data source should change.

For a fair experiment:

- keep the architecture, optimizer, update count, phase weighting, and evaluation seeds identical;
- condition CVAE generation on phase/history or generate action chunks rather than isolated actions;
- do not add numeric noise to an observation and keep the old action near phase boundaries;
- perturb simulator states and ask the expert to relabel them;
- fit normalization and generative models only on training episodes;
- use multiple training seeds and at least 100 final evaluation episodes;
- report `ever_lifted`, `ever_crossed`, `ever_released`, `retreated`, native success, strict success,
  collisions, and categorized failures.

Seeds that were inspected during debugging should become development seeds. A separate untouched seed
range should be reserved for the final comparison.
